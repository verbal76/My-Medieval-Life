# Owner directive 2026-11-10: My Medieval Life — GitHub Actions Testing Directive (verbatim, as given in the session)

Effective immediately: Move as much Build 25 testing as technically practical to GitHub Actions. The local development environment has limited disk space and should not be responsible for long-running or resource-intensive testing when GitHub Actions can perform it.

1. Move testing to GitHub Actions: full Godot regression suites; individual feature and subsystem tests; save/load integrity and determinism testing; ND-12, ND-15, and ND-16 verification; the existing 33-finding baseline comparison; all required fix-branch verification gates; economy and population simulations; 365-day campaign simulations; multiplayer automated tests that can run in CI; cross-platform build verification where practical; release qualification tests. Keep only testing that genuinely requires local hardware, interactive gameplay, or unavailable CI resources on local machines.

2. Break up long-running tests: separate testing into independently executable jobs (fast unit and subsystem tests; save/load and determinism tests; economy and inventory tests; population and migration tests; multiplayer automated tests; long-duration simulation campaigns; build and packaging verification). Run independent jobs in parallel when practical. A failed job should not automatically require rerunning unrelated successful tests. Use GitHub Actions artifacts to preserve logs, reports, simulation summaries, failure details, and reproducibility information.

3. Optimize Actions usage: limited budget. Reuse existing workflows rather than duplicating them. Cache dependencies and build tools where appropriate. Avoid unnecessary full repository builds. Use targeted tests for small changes. Reserve complete regression and campaign runs for appropriate integration gates. Avoid repeating expensive simulations when existing verified results remain applicable. Cancel superseded runs only when they are no longer needed and no evidence will be lost. Measure actual workflow durations and Actions consumption. Do not sacrifice verification quality merely to reduce runtime.

4. Preserve testing integrity: every test result must identify repository and branch, exact commit SHA, test configuration, random seed where applicable, save precision regime, expected and actual results, GitHub Actions run ID and artifact location, pass/fail/unresolved status. Never automatically accept a changed baseline simply because tests fail. Never replace an existing baseline without approval. Investigate unexplained differences before declaring a test successful.

5. Apply immediately to current Build 25 work: use GitHub Actions for the remaining Batch 3+4 comparison and fix-branch gates. Run the approved F015/P99 seed 3 and 4 campaigns in GitHub Actions, subject to available budget and runner capacity. Move the controlled seed-2 experiment into CI once its experimental implementation is ready. Complete ND-15 and ND-16 verification through CI. Continue the approved 69-item development plan, automatically dispatching the appropriate CI checks as fixes become ready.

6. GitHub Actions should become the default: Claude develops and investigates → GitHub Actions executes tests → Claude reviews evidence → verified changes become eligible for integration. Local testing should be limited to quick development feedback and tests that cannot reasonably run in GitHub Actions.

7. Report: which tests were moved; which still require local execution and why; which workflows are running; estimated Actions consumption from measured runtimes; tests that could not be migrated; whether the local disk limitation still blocks meaningful development. Record the testing architecture and decisions in the repository so future sessions follow the same standard.

Authorized to implement without additional approval, provided it does not alter gameplay, discard test evidence, change accepted baselines, or exceed the available Actions spending limits. Implement it, verify that the workflows run successfully, and make GitHub Actions the default testing environment going forward.
